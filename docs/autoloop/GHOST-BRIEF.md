# Ghost brief (autoloop): walk the world, feel what is wrong, give the user a decision

You are the "ghost". You walk a 3D Pokémon Emerald map the way a player would, find the places that feel flat, hollow
or floating, and hand the user ONE sheet of at most 10 cards. The user judges the cards. You decide nothing alone and you
change no game code. Read `docs/autoloop/FIXER-BRIEF.md` first: its Tools section has the exact commands and their
rules (max 4 games machine-wide, start yours 20 s apart, check `pgrep -fl "MacOS/love"` first).

## Scope of v0
Only `EM_ROUTE112`. Spots are in `docs/ledger/outdoor_spots.txt` (lines "MAP x y").

## Steps, in order. Stop and write down what failed if a step does not work; do not improvise around it.
1. WALK. For every Route 112 spot capture levels 4 (player), 6 (low), 7 (orbit) at yaw 0.8 and 3.9:
   `AUTOLOOP_RC=<rc tree> tools/autoloop/shots.sh <outdir> "{'EM_ROUTE112',x,y},..." 4,6,7 <yaw> 150`
   rc tree = `~/Documents/Emerald/.autoloop/rc`. Output to `~/Documents/Emerald/.autoloop/runs/ghost/`.
2. FEEL, cheap senses first (no model needed). For each spot compute, with python3 + PIL + numpy:
   - detector hits in view: `python3 tools/autoloop/detect.py air|void|steps <geo.gz>` (geometry from
     `engine/geo.sh --tree <rc tree> --maps <maps.txt> --out <dir>`; resolve tags with `--lib <rc tree>/lib`);
   - pixel difference against the original 2D art for the same cells: crops come from
     `python3 ~/Documents/Emerald/.dsh/skills/emerald-terrain/scripts/crop2d.py <slot> <pair> x0 y0 x1 y1 out.png 6`;
   - stretched or striped texture: long runs of near-identical pixel rows or columns in one object.
   Give each spot a score; keep the 20 worst.
3. JUDGE the 20. Open the full 1280x720 frame (crop and enlarge with nearest-neighbour, never judge from a thumbnail) and
   answer REAL / FALSE / UNCLEAR with a pixel box and one sentence. User taste: original pixels 1:1, never stretched;
   soft rock is fine but rounding at most ~3 px; nothing wonky, melted, striped, chunky or floating.
4. OUTPUT, the part the user sees:
   - `ghost/heatmap.png`: the map from above, spots coloured by score.
   - `ghost/sheet.html` (self-contained, images inline or relative): at most 10 cards, worst first. Each card has the
     original 2D crop, our 3D frame with the pixel box drawn, one line "what feels wrong", one line "proposed action", and
     three buttons KEEP / REJECT / LATER. The buttons write the card id and the answer into the page and a
     "copy answers" button copies them as JSON.
   - `ghost/REPORT.md`: 10 lines at most. What you did, what did not work.
5. CHECK YOURSELF. Did the 10 cards include the known faults F032 (Route 112 around 12,21, green plates and striped
   wall) and F035 (striped canopy plate in the sky at -5,42)? Say yes or no for each, and if no, which sense was missing.

## The user's answers
Saved as `docs/ledger/taste.json`: a list of {card id, map, cell, class, answer}. Later judges use these as examples.
Do not edit this file yourself except to append the answers the user gives you.

## Rules
- Report only. Do not edit `lib/`, do not commit to the rc repo, do not merge anything.
- Never claim something is fixed or fine without naming the frame file you looked at.
- If a command fails twice, write the exact command and error into REPORT.md and stop.
