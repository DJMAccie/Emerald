## 1. How the 3D scene loads and rebuilds today

- Per frame: `M.draw` → `prepare` → `request` (`MOD/lib/Gen3Scene.lua:3111-3112`, `2633-2634`, `377`). `request` is local, so a debug gate has to live inside `Gen3Scene.lua`.
- Window origin `bx,bz = floor(px/96)*6, floor(pz/96)*6` (`Gen3Scene.lua:381`): 96 px = 6 cells, so the origin moves in 6-cell steps (documented in `REPO/docs/ENGINE-DECISION-2026-10-21.md:92-95`). Window = `x0..x1` = `bx-radius .. bx+radius+6` cells (`Gen3Scene.lua:388`), i.e. 70x70 cells at the default AUTO (32-cell) radius.
- Build budget: `budget = Distance.radius()` (`Gen3Scene.lua:382` = `MOD/lib/RenderDistance.lua:23-33`; AUTO on desktop = 32 cells -> 512 px -> `radius` 32 cells, `RenderDistance.lua:26-29,33`). `radius*2+12` is the world-list reach (`Gen3Scene.lua:386` -> `ENG/src/core/game3/map.lua:130`).
- Bounds: only when `budget` is nil does the build switch from the player window to **all regions** (`Gen3Scene.lua:389`, `MOD/lib/BoundaryScenery.lua:39-46`). `budget` is nil only for R.DIST=FULL (`RenderDistance.lua:19-25`). That FULL path is already "build every region whole" — the cheapest existing knob.
- Regions: `Boundary.regions(def, Map.world)` = current map at 0,0 plus every placed neighbour (`MOD/lib/Gen3Boundary.lua:18-30`). `Map.world` is BFS over `mapDef.connections`, 2 hops minimum plus everything inside the reach window (`ENG/src/core/game3/map.lua:71,73-120`, placement offsets `102-110`). At Littleroot (reach 76 cells) this is already **13 maps / 18,180 real cells**, while the player window covers only 4,900 cells.
- Key: `SceneCache.key(regions,x0,z0,x1,z1,tiles,cam)` (`Gen3Scene.lua:398-399` -> `MOD/lib/Gen3SceneCache.lua:4-20`). `x0..z1` is in the key (`Gen3SceneCache.lua:6`), so moving 6 cells is a new key; battle centre is in the key but yaw deliberately is not (`Gen3SceneCache.lua:21-31`).
- Stream: 3 scenes kept, `keepStale=true` (`Gen3Scene.lua:316-317`); a key change starts a whole-window build, shows the old scene, and a different context returns nil so the caller draws the flat map (`MOD/lib/SceneStream.lua:44-47,62-63,83-99`; flat fallback `MOD/lib/Gen3Integration.lua:77,91`). Evicted scenes release their meshes (`Gen3Scene.lua:294-314`); R.DIST changes invalidate everything (`Gen3Integration.lua:232`, `Gen3Scene.lua:3284`).
- Stats: `M.streaming = stream.stats` (`Gen3Scene.lua:318`), fields `started/completed/cancelled/hits/reused/kept/evicted/slices/maxSlice/buildMs` (`SceneStream.lua:17,77-81`); `M.prepares/builds/cacheHits` are published for tools (`Gen3Scene.lua:2673`); `M.distance={radius,full,regions,bounds}` (`Gen3Scene.lua:825`) says whether a build was whole-world.
- First area: `M.NEAR=14` (plus 8 north rows for fixed cameras) builds a small window first (`Gen3Scene.lua:370-373,2642`), then an upgrade build (`2645-2647,2679`), with `firstAreaBuilt` for cheap models (`811-818`). Slices: `M.NEAR_STREAM=.014`, `M.STREAM=.008`, cold `.120/.060/.040` (`Gen3Scene.lua:373,376,2662`; slicing `MOD/lib/BuildBudget.lua:25-32`). Tilesets gate the build (`Gen3Scene.lua:346-366`, 180-frame cap `341`).
- Fog keys off the same function: `R.fog = Distance.haze(background, M.fadeExtent, ..., M.distance.bounds)` (`Gen3Scene.lua:3206-3207`), and `haze` only uses the scene bounds when `RenderDistance.radius()` is nil; otherwise it fades from `radius-96` px (`MOD/lib/RenderDistance.lua:81-90`). A bigger build without a nil radius still ends in haze 26 cells out.
- Cost of the current design: 1.1-1.4 s of CPU per window, thrown away every six cells (`REPO/docs/ENGINE-DECISION-2026-10-21.md:9,100-105,107-109`). That document's answer is stable sections + baked streams (`114-122`), explicitly out of scope here.

## 2. Where player collision is enforced, and the cheapest override

- Entry point: `Collision.canEnter(game,tx,ty,opts)` (`ENG/src/core/game3/collision.lua:1035`). In order: out-of-grid -> `"bounds"` (`1044`, `inBounds` `241-245`); edited/override tiles (`1045`, `1021`); directionally impassable metatiles (`1047`); elevation mismatch (`1051`, `947`); entity/NPC (`1062`, `1000`); water on foot (`1072`); unwalkable collision byte (`1073`, `914-925`, ledges rejected in `767-775`).
- `Player.tryMove` (`ENG/src/core/game3/player.lua:516`) tries `Collision.ledgeLanding` first (`540`, `collision.lua:1092-1121`), so a ledge matching the facing is a 2-cell hop; then `canEnter` (`554`); a refusal returns `"blocked", why` without starting a step (`608`). `"bounds"` is the **only** refusal that attempts a map crossing (`604-607`).
- Cheapest debug override, already written and tested: TOUR swaps `canEnter` so every refusal **except** `"bounds"` becomes a pass, `ledgeLanding` returns nil (no jump state), `tryMove` is marked so NPC/script movement is untouched, and gate/acro-bike checks are stubbed (`MOD/lib/TourMode.lua:3-9,58-101`). That covers (a) collision off and (b) walking over ledges/water/elevation/NPCs in one switch; elevation still updates through `beginStep`/`updateElevation` (`player.lua:359-366`), but nothing refuses the step.
- What TOUR keeps, on purpose: map edges (`TourMode.lua:9`), warps (doors/stairs, `TourMode.lua:14-15`), and saving is refused (`163-179`). That is why the user still has to find the entrance.

## 3. Connections, edge crossings, and why a border is not an entrance

- A crossing is only tried when the step leaves the map's collision grid (`player.lua:604-607` with `why=="bounds"`). Without TOUR a solid border cell stops the player one cell earlier with `"tile"` (with TOUR that refusal is passed, `TourMode.lua:64`), and with no cell outside the grid no crossing is ever attempted.
- Connection lookup is `Connections.incoming(mapDef,dir,x,y)` (`ENG/src/core/game3/connections.lua:59-76`, clamp `52-57`; list from `Connections.each`, `19-50`). It needs an entry in `mapDef.connections` for that direction **and** an along-edge coordinate inside the neighbour's span (`coordInIncoming`, `52-57`); otherwise nil -> `tryConnection` returns false (`collision.lua:798-803`).
- Landing is mirrored by `Collision.connectionLanding` (`collision.lua:742-762`): up -> `(x-offset, destH-1)`, down -> `(x-offset, 0)`, left -> `(destW-1, y-offset)`, right -> `(0, y-offset)`. Then `tryConnection` (`780-879`) refuses on: no landing (`806-807`), landing not walkable or water without Surf (`812-819`), LEAVE_BLOCKED/ENTER_BLOCKED behaviours (`821-824`), Surf elevation (`825-835`), ghosts (`836-837`). On success it loads the map and parks the player one cell before the landing so the step continues (`843-869`, incl. `Player.syncSavePosition` at `869`).
- So a visible neighbouring area is blocked for three independent reasons: (i) no connection entry for that edge; (ii) the connection is narrower than the edge (offset/coord clamp); (iii) the landing cell fails a test (tree/wall border, water, elevation, ghost). Plus (iv) the border cell you must step from can itself be solid.
- To walk off **any** edge into a neighbour at the mirrored coordinate: take the world cell `(gx,gy) = (fromX+dx, fromY+dy)` (current map sits at 0,0), find the `Map.world` entry with `0 <= gx-e.ox < e.def.midLayout.width` and same for y (`map.lua:96-116`), and load it at `(gx-e.ox, gy-e.oy)`. That is the same coordinate `connectionLanding` computes, but for a connectionless edge. No entry (void, boundary fill, indoors) -> stay blocked. Note: `Map.world` entries use `ox/oy` (`map.lua:116`), `Boundary.regions` entries use `x/y` (`Gen3Boundary.lua:26`) - do not mix.

## 4. Implementation plan (smallest safe diff)

**Gate.** Reuse the existing `tour` key (`Gen3SceneOptions.lua:25`, already ON for the user) and read it loader-backed, `V.mod.options:get('tour')` (`ENG/src/mods/Loader.lua:1607-1615`), not through a cached `ModSetting` index: mod module instances differ between builder and driver, so a cached index hides a QA driver's write. Add one tiny `DebugWalk.lua` (or a local function in `Gen3Scene.lua`) returning that boolean; normal play untouched when false. Because the user's save already has `tour = true`, (a)+(b)+(c) will switch on for them at the next update; if the preload should be opt-in on its own, add a second row `PRELOAD` following `Gen3SceneOptions.lua:25-27` and gate (a) on it while (b)/(c) stay on `tour`.

**(a) Whole current map + direct neighbours, once per map entry.** Add `RenderDistance.forceFull` and honour it at the top of `RenderDistance.radius()` (`MOD/lib/RenderDistance.lua:23-24`); `Gen3Scene` sets it from the gate each frame (`local Distance=V.require('RenderDistance')`, `Gen3Scene.lua:22`). That has three effects: `budget` becomes nil so `request()` takes the all-regions bounds path (`Gen3Scene.lua:389`), fog switches to the scene bounds (`Gen3Scene.lua:3206-3207`, `RenderDistance.lua:81-85`), and line `383` falls back to radius 64 -> reach 140 (21 maps at Littleroot), so pass `M.DEBUG_REACH` (32 cells) to `Map.refreshWorld` at `Gen3Scene.lua:386` instead of `radius*2+12`. Then replace `regions` (`387`) with a filtered world: current map + entries whose id is in `Map.neighbors` (`ENG/src/core/game3/map.lua:36-67`) if the union fits a cell budget. Knobs: `M.DEBUG_PAD` (bounds padding, `Gen3Scene.lua:389` currently 16), `M.DEBUG_CELLS` (~12000), `M.DEBUG_COLD` (slice, `2662`). In `prepare()` force `near=false` under the gate (`2639-2647`), and set `stream.capacity=1` (`MOD/lib/SceneStream.lua:16,36`) so a single whole-world scene is retained. With bounds constant, walking inside a map keeps `regions` and key (`399`) -> `SceneStream` hit (`45-47`), i.e. no 6-cell rebuild. Guard out `cam.battle`/`cam.replay`, where geometry must stay camera-exact (`Gen3Scene.lua:400-403`).
Measured size of the scope (QA census, `QA data/map_tree/census.json`; cost extrapolated at 0.22-0.29 ms/cell from the 1,096/1,413 ms windows in `ENGINE-DECISION:100-105`): Littleroot 20x20 + Route101 20x20 = 800 real cells in a 20x40 rect -> **3,744 cells with pad 16 (~0.8-1.1 s)**, cheaper than today's 4,900-cell window. But a city is not: Rustboro 40x60 + Route115/104/116 unions to a 140x220 rect (10,800 real cells over 4 maps) -> **43,344 cells with pad 16 (~9.5-12.5 s)**; Route112 140x140 (10,400 real) -> 29,584; Slateport 120x223 (12,120 real) -> 38,760. Hence the cell budget: above `M.DEBUG_CELLS`, keep only the current map (Rustboro alone with pad 16 = 6,624 cells, ~1.5-1.9 s). Never build all of `Map.world`: at Littleroot it is 13 maps/18,180 cells and its bounding rect is 69,360 cells with pad 16.
**(b) Collision-free movement.** Nothing new: TOUR already does it (`TourMode.lua:58-101`), same gate.
**(c) Cross any edge.** Add one spec to `TourMode.SPECS` (`TourMode.lua:58-180`) wrapping `Collision.tryConnection` (tbl `src.core.game3.collision`, key `tryConnection`): call the original; if it returns true, done; if false and the gate is on, run `crossEdge()` as in section 3 - world-cell lookup, `Map.load(mod,game,id,{x=lx,y=ly,facing=dir,seamless=true,depth1Connections=true})` plus the park/sync lines copied from `collision.lua:851-869` - and return false when no entry exists. `mod` comes from `Runtime._mod` (`collision.lua:839-841`). `tryConnection` is also called from the acro-bike path (`ENG/src/core/game3/bike/rse.lua:229`); keep the wrap behind the gate and behind the same `inMove` marker where possible.

Risks, each with its gate check in section 5:
- **Build cost**: whole-neighbour builds are 4-12 s on cities (numbers above); the cap plus pad are the only knobs, and a cold build still holds the flat map for its whole duration (`SceneStream.lua:98-99`). This is a *preload*, not a free lunch: entry gets slower, walking inside a map gets free.
- **Fog/culling**: forcing full is not cosmetic - `haze` only trusts the scene bounds when `radius()` is nil (`RenderDistance.lua:81-85`), and the same nil also disables `RenderDistance.point/neighbor/section` culling (`47-77`, used by the Gen1/2/composite modules) - set the flag from the gate every frame and clear it when the gate is off.
- **Memory**: 3 retained scenes (`Gen3Scene.lua:316`; retire `SceneStream.lua:33-39`) would be 3 whole-world scenes -> capacity 1 in debug; measure `M.retainedGeometry()` (`Gen3Scene.lua:3266`).
- **Tilesets**: the whole-region request waits for every region's tileset before the first cell (`Gen3Scene.lua:346-366`, cap `341`); at Littleroot that is more pairs than today, up to 3 s more flat map.
- **Saves/warps**: TOUR refuses saves (`TourMode.lua:163-179`); doors/stairs still warp (`TourMode.lua:14-15`) and every `Map.load` resets the encounter grace and captures ghosts (`ENG/src/core/game3/map.lua:470-476,499`) - harmless with TOUR's encounter/step stubs (`TourMode.lua:103-161`).
- **Indoor maps**: no connections -> `Map.world` is just the map (`map.lua:73-120`); `VOID_BY_MAP` cells are skipped (`Gen3Scene.lua:840-846`) so interiors stay cheap, and warps remain the only exit (correct).
- **Boundary fill**: bounds are the bounding rectangle of an L-shaped set, so concave corners are fill (`Gen3Scene.lua:842-845`), which is drawn but has no map/collision; crossing only ever enters real maps.
- **Scene identity**: a cross-map `Map.load` clears `Map._worldRoot` (`map.lua:508`), regions are rebased on the new root, so each crossing is one rebuild - accepted by the chosen scope ("built once on entry").
- **Normal play**: gate false -> same budget (`382`), same key (`399`), capacity 3, NEAR first area (`2639-2647`); TOUR already restores every wrap on OFF (`TourMode.lua:206-215,219-235`).
